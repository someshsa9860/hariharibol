# App — HariHariBol Mobile

Flutter app (iOS + Android). Clean, simple, conventional. No clever architecture.

**Status:** everything here is unit/widget-tested against fakes; very little has run on a phone or a live API, and every non-English string is AI-drafted (no native reader). Tests for a feature are `test/<feature>*_test.dart` — look there, this file does not list them. This file holds rules and traps, not history; git has the history.

## Non-negotiables

1. **Nothing is hardcoded.** No magic strings, colours, sizes, durations or endpoints inline — l10n, theme tokens or config (`core/constants/*_config.dart`).
2. **Standard localization** (ARB + generated delegates). Every user-facing string goes through it.
   - **Text added to `lib/l10n/app_en.arb` is translated into every other `app_*.arb` in the same change** (`hi mr gu bn ta te kn or pa ml as`; no Sanskrit UI file). Same keys, same order, no `@key` metadata (English only), same placeholders / ICU shape, Latin digits. Then `tool/flutter.sh gen-l10n` and commit `lib/l10n/generated/`. If an English text's *meaning* changes, re-translate everywhere or use a new key. `gen-l10n` only warns (the app then silently shows English), so `test/l10n_parity_test.dart` enforces it; CI doesn't run app tests — run it. House style / glossary: [lib/l10n/README.md](lib/l10n/README.md).
   - **Services write no words.** A failure made on the phone has an empty `message` and a `FailureKind` / `ClientFailureCode`; screens show `failure.describe(AppLocalizations.of(context))` (`core/format/failure_text.dart`). Never show `failure.message`. The chat is the exception: `failure.ownWords(...)`, never the server's wording.
   - Quotes, dashes and joins are copy too (`labelQuotedMeaning`…). Dates and money use `Localizations.localeOf(context)`, never the device default.
   - The app-language setting drives the UI locale (`providers/locale_provider.dart`) for any language with an ARB (all twelve).
3. **One colour system** in the theme, used everywhere.
4. **Not styled as a "spiritual app."** Standard patterns, consistent colour, padding, spacing.

## Toolchain

**Flutter 3.44.2 / Dart 3.12.2**, pinned in `.flutter-version`. Run everything through [tool/flutter.sh](tool/flutter.sh) (`test | analyze | pub get | gen-l10n`; `./run.sh`, `./build_bundle.sh`, `./build_ipa.sh` already do). A bare `flutter` or an IDE Dart daemon on the wrong SDK leaves `.dart_tool` broken (`Invalid kernel binary format version`, `ui.HitTestResponse` not found) — not a code bug; the next `tool/flutter.sh` run repairs it. VS Code: set `dart.flutterSdkPath`. To move SDK change `.flutter-version` and `pubspec.yaml` (`sdk: ^3.12.2`) together.

## Build-time configuration

Nothing per-environment is committed; every `--dart-define` has a working default.

| Define | Default | Why |
|---|---|---|
| `API_BASE_URL` | `https://api.hariharibol.com` | Point a debug build at a laptop (Android emulator host = `10.0.2.2`). |
| `GOOGLE_SERVER_CLIENT_ID` | — | The **web** client id; Android needs it as `serverClientId` or Google returns no ID token. |
| `GOOGLE_IOS_CLIENT_ID` | — | Normally from `GoogleService-Info.plist` (a secret). |
| `TTS_MODELS_MANIFEST_URL` | bundled `assets/tts/tts_models.json` | Replaces the voice manifest at run time. |
| `WS_URL` | `/ws` on the API host | Live socket (developer chat). |

- **Play bundle:** `./build_bundle.sh` → `build/app/outputs/bundle/release/app-release.aab`. Always `https://api.hariharibol.com`, **ignores `API_BASE_URL` in `config.sh`**; `RELEASE_API_BASE_URL=https://…` overrides, non-https refused. `shrink=false` in `android/gradle.properties` (no R8). Build number is the `+N` in `pubspec.yaml` — raise before each upload. `build_ipa.sh` has no production guard.
- **Firebase is optional at boot:** `FirebaseService.init()` catches its own failure; push/analytics go quiet, App Check returns no token, the rest works (backend `APP_CHECK_ENABLED=false` in dev is the other half).

```
app/lib/
├── main.dart            # boot only — storage, device, firebase, session, legacy sign-in, runApp
├── app.dart             # MaterialApp.router: theme, l10n, router
├── l10n/                # app_en.arb + 11 app_xx.arb + README.md + generated/
├── core/{theme,constants,navigation,session,layout,format,share_links.dart}
├── models/              # every model, plus json.dart's parse helpers
├── db/                  # Drift: tables, DAOs, offline library
├── repositories/        # BookRepository — what screens ask for book text (local first)
├── providers/           # Riverpod, one file per feature (connects a service to a view; not a layer)
├── views/{splash,auth,dashboard,...}   # one level deep; one dart file per tab
├── widgets/{common,auth,chat,dashboard,...}
└── services/            # api_client, auth, fcm, tracking, …  one self-contained file each
```

- **500 lines max per dart file.** Views are thin layout/wiring; custom widgets live in `widgets/{module}/{name}.dart`. Over the limit today: `chant_view.dart` (~860, must not grow; the picture-in-ring and pace/prayer logic are next to lift out) and `chapter_read_view.dart` (~517; favourite/highlight toggles next).
- **Riverpod everywhere** — no second state solution; a Drift stream becomes a provider directly. **Drift** (SQLite, FTS5) holds the offline library. Do not use Realm, Isar, or original `hive` (use `hive_ce`).
- **go_router through one navigation singleton** (`AppNavigator`); views never touch `Navigator`. It also owns the loading handler.

## Design language

Editorial layout on warm paper, not a Material dashboard.

- Palette `core/theme/app_colors.dart`; both `ColorScheme`s written by hand in `AppTheme._scheme`. **Never `ColorScheme.fromSeed`.**
- Headings `AppTypography.serif` (Georgia / Noto Serif, none bundled) at regular weight — hierarchy by size and space. `AppTypography.numeral` for counts. **Devanagari never takes the serif** (`AppTypography.verse`, extra leading). `AppTypography.eyebrow` (`widgets/common/eyebrow.dart`): sentence case in, widget uppercases.
- `Motif` / `MotifPanel` (`widgets/common/motif.dart`): drawn line art, the fallback for a missing image — never a grey box.
- Cards are a lighter plane with **no border** (`cardTheme` does it; no hand-rolled `BoxDecoration`). **No control that does nothing.**

### The colour rule

**Light = medium orange, saffron, warm white. Dark = soft charcoal and white. No fourth colour.** Light has no grey (neutrals are tints of the one hue); dark has no orange (accent is white).

- Never `Colors.*` except `transparent`; no `Color(0xFF…)` outside `app_colors.dart`. Saffron is a fill, never text (2:1 on white); what sits on it is `ink`.
- **One exception, in the routine tab:** how on time a ticked task was — yellow early, green on time, red late (`AppColors.early/onTime/late`) — plus weekday initials in the date strip. Never alone: each has a word and a check mark. `test/routine_status_test.dart` holds 3:1 contrast.
- **Colour never carries meaning alone** — every state also has an icon or word. `test/palette_test.dart` checks hue and 4.5:1 contrast.

## The chant counter

`views/chant/chant_view.dart` owns state. `ChantRecorder` (`services/chant_recorder.dart`, pure Dart, injected clock) stamps every tap: a round is the next `beadsPerRound` taps; a chant's duration is its **gap** since the previous tap (a sitting's first tap has none, left out of averages). Taps stay in memory; a round goes up as a summary (`ChantMalaLog.toJson`); analytics show rounds only. A round carried over from an earlier sitting has no duration ("–", excluded from averages and fastest). Counting is written to the phone first and sent later — see "Chanting kept on the phone, sent in batches". The counter never waits on the network.

- **Auto count counts sound, at the mantra's own pace.** Silero VAD (`mantra_detection_engine.dart`, the only model) + `voice_chant_counter.dart` (pure Dart, injected clock): one chant per pace of sound, none while silent, a last unfinished chant counts at ≥ 60% (`partialChantShare`). Nothing is recognised (a word recogniser was tried and removed — it wrote gibberish for Sanskrit; `Mantra.chantWords` and the admin field remain, unread). A mantra with no standard time uses 0.1 s × letters, min 1 s (`MantraAutoChantSession.standardChantMsOf`) — set the real `Mantra.durationMs` in admin (mahamantra 4000).
  - **Pace** is one number per mantra (`services/chant_pace.dart`, stored `BoxKeys.chantPace(mantraId)`): starts as the standard time, held to 45%–300% of it (`AutoChantConfig.fastestShare/slowestShare`); never counts faster than 45%. Moved by shorter/longer buttons (`widgets/chant/chant_pace_row.dart`, 5% steps, min 100 ms) and by a finished round (`ChantPace.ofRound`: real round time minus the prayer's standard time, over its chants). **Not learned** from a part-way round, one with no prayer tap before it, one the app was backgrounded in, a mala-recording round, or after a hand-set pace (stands until a clean round). `VoiceChantCounter.changePace` re-bases without stalling.
  - **Switch off:** a hand tap sooner than half the pace after the last is ignored (`manualTapGapOf`); the first tap of a sitting and any tap with no mantra are taken. **With auto count running or the mala recording in use, a ring tap does nothing** (`ChantView._tapRing`, shared with the full-screen picture) — the prayer's tap excepted. Undo and Finish round always work. Teaching a faster pace = tap ahead or press "shorter".
  - **Microphone optional** (`BoxKeys.autoChantMicrophone`, absent = on). Off → timer mode (`AutoChantSource.timer`, `VoiceChantCounter.startSteady`): one chant per pace, no mic/permission/detector; `MantraAutoChantSession.useSource` restarts on switch. Foreground-only, no catch-up.
  - **The switch** (`widgets/chant/auto_chant_switch.dart`, inside `chant_auto_card.dart` with the pace row) is remembered (`BoxKeys.autoChantEnabled`); the counter starts listening on open if left on; leaving frees mic, detector isolate and model (`MantraAutoChantSession.dispose`). Switching on shows `ChantAutoLoadingDialog`. No mantra → no switch.
  - **Foreground only:** `paused` stops and remembers, `resumed` restarts. Background listening deliberately not built (Android 14+ needs a mic foreground service). Starts/stops run one at a time. Session builds its own mic/engine, so it has no unit test.
- **Opening prayer** (`Mantra.prayer`, one level; mahamantra → Panchatattva; admin Mantras page, "Opening prayers" in [backend/CLAUDE.md](../backend/CLAUDE.md)). The counter opens on the prayer (name, text, `chantPrayerHint`), auto-count card held back. A ring tap after the prayer's standard time brings up the mantra; **that tap is not a chant** (`ChantRecorder.beginChanting()` starts counting there). **It returns before every round:** the last bead shows the prayer, suspends auto count and pauses/rewinds a mala recording. A round picked up part-way isn't asked for its prayer. `ChantView` takes a `clock` for tests.
  - **No own prayer → every round ends with kṛṣṇārpaṇamastu** (`services/fallback_prayer.dart`, name `chantPrayerFallbackName`, 3 s), only at a round's end, never on open. Written in the reading language's script (`fromDevanagari`), built at first round end via `ref.read(readingChainProvider)` — widget tests finishing a round on such a mantra must override it (needs `LocalStore`). AI-drafted Sanskrit: have each script read.
- **Finish round:** past 90 of 108 beads (`SadhanaConfig.finishableAfterBeads` / `standardRoundBeads`, scaled to beads per round; `canFinishRound`) a button (`chantFinishRound`, `chant_round_actions.dart`, beside Undo) closes the round for a reader who chanted the rest on their own mala. `ChantRecorder.finishRound()` fills the gap with filler taps (`ChantTapLog.filler`: counted, kept out of pace/averages), learns no pace, no confirmation, Undo dimmed after. The 90 is a code constant, not admin.
- **Screen split:** `chant_view.dart` owns state; `services/chant_session_sync.dart`, `widgets/chant/{chant_mantra_text,chant_auto_card,chant_pace_row,chant_toggle_row,chant_round_actions,chant_auto_loading_dialog}.dart` are lifted out.
- **The round in progress is kept per mantra** (`ChantProgressStore`, `BoxKeys.chantProgress(mantraId)`, `any` for the plain counter; written every bead/undo, forgotten when a round completes). Reopening starts the recorder there (`ChantRecorder.carry`). No restart button — undo goes back bead by bead. **Ring and count line are that mantra's own rounds** (`roundsBeforeSitting(...).mantra`: 16 mahamantra + 1 Om Namah Shivaya read 16 and 1); **"n of goal" and the target check are the day's** (`.day`).
- **Analytics are for the counter's mantra, rounds only** (`ChantAnalyticsView`, `GET /chant/sessions?mantraId=`, `none` for plain counter; `chantHistoryProvider` family on mantra id). Word transcripts are no longer recorded (`attachHeard` etc. remain, unfed).
- **The deity on the counter:** `Mantra.deity.imageUrl` (list) / `fullImageUrl` (9:16). A deity picture fills the ring's middle with no number over it (`ChantDisc.pictureUrl`); the count moves to one line under (`chant_disc_count.dart`; `MalaRing.showCount` otherwise). One expand button on the picture's rim (`ChantDisc.onOpenPicture`) opens `chant_fullscreen_view.dart` (cover for 9:16, contain for the list picture) where **any tap is a bead**. With a picture, tests tap `find.byType(TapScale)`, not `ChantDisc`.
- **The day's rounds are never capped at the target:** the figure after the slash is `SadhanaDay.roundGoal` (`roundGoalFor`, rungs in `core/constants/sadhana_config.dart`): the target while at/under it, then 32, 64, 108, then next multiple of 16. "Target met" and Settings still mean the person's own target.
- **"Chant now" opens the mantra you keep chanting:** `SadhanaToday.chantMantraSlug` = profile choice, else `favoriteMantra` (most rounds over 60 days), else the plain counter.
- **Closing is instant:** close/back stops the recording and pops in the same frame; the final sync (`ChantSessionSync.send(finish: true)`) and the Jap/Home refresh run afterwards (`ChantView._finishSitting`), failures swallowed. Read the notifiers *before* the pop. Taps after close are ignored (`_tapBead`). The finish is written to the ledger first, so closed offline it goes with the next batch.
- **Chant along** (`Mantra.malaAudioUrl/StartMs/EndMs`; `hasMalaAudio` false unless end > start). `widgets/chant/chant_along_card.dart` plays it (`chant_mala_timing.dart` pure, `chant_mala_player.dart` on `just_audio`); the stretch is shared evenly among a round's beads and a chant counts as it **finishes**. Other halves: [backend/CLAUDE.md](../backend/CLAUDE.md), [admin/CLAUDE.md](../admin/CLAUDE.md).
  - Only listening counts (a seek, or a jump > `ChantAudioConfig.continuousStep`, counts nothing; replaying counts again).
  - **Playing is the prayer:** start 0:00 → the on-screen prayer is the whole prayer and play ends it (`chantPrayerHintAlongNoPrayer`); later start → those seconds are the prayer, count begins when playback reaches the start (`chantPrayerHintAlong`). Never said twice. A failed recording keeps `chantPrayerHint`.
  - **Play from rest begins where the count stands, not at 0:00** (so chants made by hand are not heard and counted twice). `ChantMalaTiming.positionAfter(n)` is the earliest position `chantsDoneAt` calls `n` (rounded **up**, else n−1 is counted), start-of-chanting for 0 and the end for all; `ChantMalaPlayer.restAt` is asked in `play()` only when the recording is *at rest* (position 0, or completed) and `ChantView._malaRestAt` answers: beads counted → `positionAfter(beads)` (past any prayer in the file); none and the prayer on screen → 0:00 (the recording says it); none and the prayer already tapped by hand → the chanting's start (never said twice); no prayer at all → 0:00. Paused part-way, or the bar dragged, play carries on from there whatever the count. The seek goes through `seek()`, so it counts nothing. Known gap: **Undo while the recording is paused part-way** takes a bead off the count but leaves the voice where it was, one chant ahead.
  - Auto count and microphone **rest while it plays** (both switches shown off and disabled, `chantAutoCountResting`); not switched back on by themselves, saved preference unchanged.
  - **Ring untappable while the recording is in use** — playing or paused part-way (`ChantView._recordingInUse`); drag to 0:00 to chant by hand. A finished round, loading, failed or unavailable hands it back.
  - Stops with the person (background, close); screen held awake while it plays (`wakelock_plus`; `ChantMalaPlayer.dispose` releases it first). A stale signed link is re-fetched once (`MantraService.get`).
  - **Offline:** a played recording is kept as a file (`MalaAudioCache`, see "Offline: saved answers and fetching ahead"). With no connection and no kept file, `ChantMalaPlayer` answers `ChantMalaPhase.unavailable` (not `failed`) via `ConnectionStatus` (`connectivity_plus`; `malaConnectionProvider`) and the card and its space are not drawn; it loads by itself when a connection returns. It knows "a network is attached", not "the server answers".
  - **Tests** swap `malaAudioPlayerProvider` for `FakeAudioPlayer`/`FakeWakelock` (`test/fake_audio_player.dart`) and pass `malaConnectionProvider.overrideWithValue(null)` (always online) or a `FakeConnectionStatus`. Under `testWidgets` a stream `cancel()` doesn't finish in `pump`, and frames stop once the lifecycle is `paused` — resume before leaving.

## The Jap tab offline

Opens, lists mantras and starts the counter with no connection. **Saved copies shown first, replaced when the network answers:** `SadhanaService.today` and `MantraService.list/categories/get` write the raw API answer under `BoxKeys.sadhanaCachePrefix` (`cache.sadhana.…`) on every success; providers read the copy before the request lands; a failed request leaves the copy standing.

- **`savedThenFresh`** (`providers/saved_then_fresh.dart`, shared with books, calendar, etiquette) starts the request *before* handing over the copy, so the cache refreshes even if a reader takes the first value and leaves. The sadhana screen does the same in `SadhanaTodayNotifier.build` (`fetch()`/`savedCopy()` overridable in tests).
- A category never opened is cut from the full list (`MantraService.savedList`); a mantra page falls back to its row in the full list (`savedMantra`). **A copy from an earlier day becomes an empty today** (`SadhanaToday.carriedTo`: goal/mantra/beads kept, streak kept only if the copy is from yesterday).
- `SadhanaTodayNotifier.refresh()` returns the `ApiFailure` (null on success) and keeps the screen; pull-to-refresh also invalidates the mantra providers.
- **Wiped on sign-out** (`AppSession.clear` → `LocalStore.deleteWithPrefix(sadhanaCachePrefix)`); the mantra copies alone are dropped when the account's languages change (`BoxKeys.mantraCachePrefix`, `_refetchServerShaped`).

## Chanting kept on the phone, sent in batches

What a reader chants is **written to the phone first and sent later**: counting works offline, survives kill, and costs no request per chant. Server half: `PUT /api/app/sadhana/chant/sync`, idempotent per sitting by `clientId` ("The chant record" in [backend/CLAUDE.md](../backend/CLAUDE.md)).

- **Ledger.** `models/chant_sitting.dart`: a `clientId` (32 hex, made once — makes a resend harmless), day, mantra, rounds, beads, finished, unsent mala details (`pendingMalas`) and what the server last acknowledged (`syncedRounds/Beads/Finished`). **Dirty** = holds anything unacknowledged. `ChantLedgerStore` (`chant.ledger`, one owner = the signed-in user id; another account's rows are never read) + `chantLedgerProvider` (in-memory copy, only writer). `keptSittings` trims on every write: synced rows stay `keepSyncedDays` (2), **dirty rows forever**.
- **Writing:** `ChantSessionSync` (per counter screen and per chanting reel) turns recorder state into a ledger row after every bead/undo/finish, then asks for a batch. No session on the server, no waiting.
- **Sending: `ChantSyncer`** (`services/chant_syncer.dart`, no Riverpod, no words; `chantSyncerProvider` read once in `app.dart`). `schedule()` is a **throttle**: first change starts a `batchInterval` (2 min) timer later taps don't restart. A send takes dirty sittings, 25 per request, ≤ 8 requests per run; > 200 malas in one sitting go over two requests. A sitting is marked sent **by what was in the request** (a bead counted in flight stays dirty). A batch refused as invalid is retried one sitting at a time; a lone refused sitting waits for the next trigger. Unauthorized doesn't retry; rate limit waits `retryAfter`; other failures back off 30 s → 15 min, reset on success.
- **Triggers** (`providers/sync_triggers.dart`, shared with routine sync): sign-in / app open signed in, foreground, background/hidden, connection returns, the timer. Signed-in only. A send from one of those moments that the server took refreshes the Jap tab's day (`syncAndRefresh`); a timer send doesn't.
- **Home, Jap and the counter lay the phone's unsent rounds over the server's day** (`chantExtraProvider`: per ledger sitting of the day, rounds minus what the server's sessions hold for the same `clientId`, never negative) — `SadhanaToday.plusRounds`, `SadhanaSummary.withPhone`; arithmetic in `models/chant_tally.dart`. A day not yet loaded shows no overlay. The mantra page's all-time `myRounds` is the server's and is not overlaid.
- **Accepted edges:** the sitting belongs to the *phone's* calendar day here vs the *account's* timezone on the server; Home/Jap don't roll over at midnight until refreshed; signing in as someone else leaves the first account's unsent rows unsent (ledger isn't cleared by `AppSession.clear`); undoing a round after it was sent leaves the server on the higher figure; a kill mid-sitting leaves the server's sitting without an end time.

## The routine tab

`views/dashboard/routine_tab.dart` (name kept from when it was a tab). **A screen of its own** pushed at `/routine` (`AppRoutes.routine`, `RoutineTab(showBack: true)`) from Home's `RoutineEntryCard` ("n of m done", live from the routine's progress provider). Strip of days (`routine_date_strip.dart`, 120 back / 60 ahead in `RoutineConfig`) over the day's list.

- **Each day has its own list.** A task is added *for* a day (`RoutineTask.day`). Optional **daily routine** (`DailyRoutineItem`) shows every day from when added, each day with its own check (`routine.checks`, `{day: {id: minute|null}}`); removing sets `until`, past days keep it. Day keys `yyyy-MM-dd` (`routineDayKey`).
- **Kept on the phone first, mirrored to the account.** `LocalStore` (`routine.tasks`, `routine.daily`, `routine.checks`) is what the screen reads; every change writes there first. Old formats migrate on read (tasks without a day → old `routine.date`; `{day: [ids]}` checks → ticked, no time).
- **Sync** (`POST /api/app/routine/sync`, "Routine" in [backend/CLAUDE.md](../backend/CLAUDE.md)). The last server answer is the **base** (`routine.synced`, records its owner); `RoutineChanges.between` (`models/routine_sync.dart`) diffs base vs now, so no change site does bookkeeping. `mergeSynced` takes the server's version of days from `since` (today − 120), keeps older phone days, lays back edits made while the request was away. **Last write wins** between phones. `services/routine_syncer.dart`: debounced 3 s after a change, one at a time, again on resume/pause/reconnect (`providers/routine_sync_provider.dart`), 30 s → 15 min backoff, **never repeated after a refusal** (400, 404, permission 403), stopped on `unauthorized`. Needs a signed-in user; 500 rows per request; titles cut to 200 chars (`routineTitle`).
- **One account's routine is never uploaded into another's:** `routine.owner`; a different account signing in shows an empty list and wipes keys and base (unsynced edits of the account that left are lost). A routine from before owners is claimed by whoever opens it first. **Nothing is written from `build()` for an empty routine** (see "Testing traps").
- **Bottom inset:** list and empty state add `MediaQuery` bottom padding + `AppSpacing.xxl`.
- **Time range:** a task may carry `RoutineWindow` (`windowStart/End`, minutes after midnight; `end > start`, `end < 1440`; invalid stored range loads as none). Ticking notes `doneAt`; `RoutineTask.status` = `pending` / `done` / `early` / `onTime` / `late` (**both ends of the range are on time**). The slot a task groups under is derived from where its range opens (`RoutineSlot.at`).
- **Add sheet** (`add_routine_task_sheet.dart`): name is an editable `DropdownMenu` over `core/constants/routine_presets.dart` (picking fills category and range); `enableSearch` is off (or "Done" swaps typed text for the first match); `menuStyle` padding zero so an empty menu has no height (it used to swallow taps on the chips). `RoutineWindowField` (From/To system picker; a start past the end carries the end to +60 min). Form scrolls, Save pinned, both above the keyboard; the tab `Scaffold` has `resizeToAvoidBottomInset: false`. New range opens 6:00–7:00.
- **Ticking:** tap ticks at now (or unticks); on a day that isn't today it asks, opening the picker at the range start. The status pill is its own button to change the time (`RoutineTab._toggle/_editTime`). Times follow the phone's 12/24h.
- **Editing, making daily, deleting.** A tile's ⋮ or a long press opens `showEditRoutineTaskSheet` (`add_routine_task_sheet.dart`, same form as Add) → `RoutineTaskEdit` (`draft`, or `delete`); a swipe deletes too.   - daily item changed → in place if it began that day, else **split**: the old item ends the day before (`until`), a new one (new id, same `until`) starts that day and takes that day's and later ticks. **Made not daily** → the item ends the day before and a one-day task stands on that day with its tick (it stops repeating after).

  - **Delete** = `removeFromDay` (a one-day task goes; a daily item gets `until` = the day before) → a snackbar with **Undo** (`undoRemoval`), which puts back the task or item and **only the ticks the removal cleared** (that day and later), so a tick made in between stays.

Numbers in `RoutineConfig`.

### Mechanics

- **Packages:** markdown is `flutter_markdown_plus` (maintained fork; `markdown` is a direct dep only for `md.Element` in builders). The UI is a custom reversed `ListView` + composer — not `flutter_chat_ui` or `gpt_markdown`.
- **Streaming without flicker** (`providers/chat_controller.dart`): deltas buffer and reach state **at most every `ChatConfig.flushInterval` (50 ms)**, first word at once; the bubble is keyed by `ChatMessage.clientKey` (same from placeholder to server message); each assistant message in a `RepaintBoundary`; list `reverse: true`; while streaming text goes through **`streamingSafeMarkdown`** (`core/format/streaming_markdown.dart`: closes an open fence / odd trailing `**` `*` `_` `` ` ``, drops a lone marker, holds back an empty fence and unfinished image; leaves `snake_case`, `2 * 3`, bullets alone). Not selectable while streaming; selectable on completion.
- **The wire** (`ApiClient.postEventStream` → `services/chat_service.dart`): Dio `ResponseType.stream`; SSE parser is its own pure file (`services/sse_parser.dart`). **`parseSse` must use `Utf8Decoder.bind(bytes)`, not `bytes.transform(...)`** — Dio's body is `Stream<Uint8List>` and `transform` type-checks at runtime, throwing a `TypeError` that read as a dropped connection while the server had answered 200 (`test/sse_real_dio_test.dart` reads a real Dio response). A refusal before streaming (402/409/400) is a normal `ApiFailure` with `code`/`details`; after it, `ApiClient.guardStream` sorts breaks: connection → `network`, stall → `timeout`, our own fault → `unknown` (**never the network**). It loops with `await for`, **not `yield*`** (which forwards errors as events so the `catch` never runs). `ApiCancelToken` closes the connection — that's how the server learns to stop and keep the partial text, charging what was used.
- **States** (`providers/chat_state.dart`): `ChatPhase` (idle / waiting / streaming) + `compacting`, `working`; `draftImage`; a failed turn becomes a `ChatProblem` with a `ChatIssue` (`offline, timedOut, connectionLost, overloaded, unavailable, replyFailed, creditsExhausted, notAvailable, conversationFull, busy, tooLong, failed`). **A question the server never saw goes back into the box** (`restoredDraft`); a partial answer stays marked *Stopped* / *Interrupted* (words). **Retry = regenerate** the last question. Leaving stops a reply in flight.
- **Failures are worded by the app, never the server** (`ChatProblem.fromFailure/fromEvent`, `ChatProblemNotice` in `chat_notices.dart`; `test/chat_problem_test.dart` feeds hostile text). Sorted **by `code` first, then kind**: `AI_BUSY`/429 → overloaded; `AI_UNAVAILABLE`/`AI_MISCONFIGURED`/`AI_BUDGET_EXHAUSTED`/5xx → unavailable; `AI_FAILED`/`AI_BAD_OUTPUT` → replyFailed; 409 lock → busy; no route → offline, but `connectionLost` once the stream's `meta` arrived (`replyStarted`); stall → timedOut; else `failed` (`ApiFailure.ownWords`). An unknown code is `failed`. **Try again only when asking again can help** (`canRetry` and the event's `retryable`; never for `busy`).
- **Credits** (`providers/chat_provider.dart`, `widgets/chat/chat_credit_meter.dart`): slim bar in the app bar, "NN% left · level", tap shows the hint. **Token counts never reach the phone and no widget can draw one.** Every `done` carries the new reading; a stopped reply is charged shortly after close so the meter is re-read `creditsRefreshDelay` later. Exhausted (402, meter, or plan has no chat) → `ChatCreditsCard` with **Upgrade** (to `/plans`, only if a higher plan exists) and the box off.
- **Markdown** (`chat_markdown.dart`, `chat_markdown_style.dart`): all from the theme; headings in sans, never serif. A **block quote is a shloka card** (`shloka_card.dart`): Indic lines in `AppTypography.verse`. Images https only via `CachedNetworkImage`. **There is no link launcher, so a tapped link is copied** (adding `url_launcher` is a later decision).
- **Tests:** `test/support/fake_chat_service.dart` (a server you play by hand: `push, finish, drop, refuseNext`), `support/fake_chat_device.dart` (camera/mic). A provider that is `autoDispose` and unwatched resets between awaits — keep it alive as the screen does.
- **Ask Sakha from a verse:** the verse action row's button (`VerseBlock.onAskSakha` → `ChapterReadView._askSakha`) pushes the chat with `extra` = `chatExplainVerse(reference, verse)` (Sanskrit + the shown rendering, cut at 1,500 chars); `ChatView(initialPrompt:)` sends it once loaded (into the box if the reader can't send).
- **Sakha can offer to open a place** (`ChatActionOffer` from the `action` event → `ChatActionCard` "Open Reels?" Open / Not now; `chatActionRoute`): nothing opens until tapped; tabs are switched to, anything else pushed over the chat; cleared by the next message / regenerate; not saved.

## Silent offline books

Opening a book makes it readable offline, no prompt. The server exports each chapter (Gita) / canto (Bhagavatam) to S3 weekly; the app downloads only what it lacks, straight from S3 ([backend/README.md](../backend/README.md#book-cache--silent-offline-books)). Flow: `BookSyncManager.syncBook` → manifest → `BookSyncPlanner` (missing / newer / different hash; open unit first, then neighbours) → queue (2 at once, de-duplicated, paused offline) → `BookUnitDownloader` (S3, timeouts, backoff, `Range` resume, one link refresh) → isolate (gunzip + SHA-256 + parse) → `BookDao.replaceUnit`.

- **`db/`** Drift schema 6 (history in `app_database.dart`): `books` (`contentVersion`), `units`, `verses`, `verse_translations` (every language of every verse incl. `wordMeanings` JSON), `download_state`, FTS5 `verse_fts` (made in `SearchDao.createIndex`, not a Drift table). `BookDao.replaceUnit` is the **one** writer, one transaction. The v5→v6 upgrade nulls every unit's `hash` so the next sync refills word meanings (until then English shows).
- **New server text is noticed** (`BookSyncManager.checkForUpdates`): the server bumps `contentVersion` on any text change and re-exports in ~2 min; the app fetches a **fresh manifest** for every held book (any `download_state` row) at launch, on foreground (≥ `updateCheckInterval` 15 min apart) and on reading-language change (forced); the planner stays the authority. Silent when offline. `Books.contentVersion` is recorded only once **every** unit is current (`BookDao.setContentVersion`; `dropOutdatedUnits` resets to 0). The open chapter reloads by itself (`BookDao.watchChapterRevision` → `chapterReadingProvider`). A check also retries units failed past `autoRetryLimit`; the background task only finishes unfinished units.
- **`repositories/book_repository.dart`** is the only thing screens ask for book text: local first; a missing unit is queued at the front and awaited (`readerWait`), then the API. Short works (no chapters) come from the API and are saved whole (`unitType: 'book'`). **Language is chosen at read time** (`pickTranslation`). **Export files carry audio keys, never links** (a link would change the hash hourly): `Verse.audioPath` key, `Verse.audioUrl` link from `/audio-urls`. A `done` unit keeps old text while a newer one downloads or fails.
- **Background** (`book_sync_background.dart`, workmanager): finishes unfinished units when backgrounded (network, battery not low); sync endpoints are public. iOS needs `BGTaskSchedulerPermittedIdentifiers`, `UIBackgroundModes: processing`, `WorkmanagerPlugin.registerBGProcessingTask` in `AppDelegate.swift` — unverified.

## Offline: saved answers and fetching ahead

Everything else openable offline: every answer worth keeping is **saved when it arrives**, and a background pass **fetches ahead**.

- **`ResponseCache`** (`services/response_cache.dart`, Hive box `BoxNames.responses`, opened in `main()`). `api.getOrSaved(path, query:)` saves a successful GET under path + sorted query and returns the saved answer **only when the server could not be asked** (no connection, timeout, 5xx — `serverUnreachable`); a 404 or refusal is never covered up. `api.saved(path, query:)` reads at once. Capped (`OfflineConfig.maxSavedResponses`, oldest out in `evictBatch`; none over `maxSavedResponseLength`). An extension (`KeptForOffline`); each service chooses which calls use it.
- **Shown first, replaced when the network answers** (`savedThenFresh`): books list / book page (`StreamProvider`s), a calendar month, upcoming festivals, etiquette. Elsewhere the copy is only the fallback.
- **Saved:** books (list, book, languages, cantos/chapters — chapter text is Drift); calendar months per language + upcoming (`savedUpcoming` drops past days); etiquette (today, list, items; an unopened item falls back to today's or its list row); prayers (list and each prayer, per reading chain; a prayer never opened has no saved copy, because a list row carries no verses); the verse page, notes, favourites, issues, languages, deities/gurus/translators, mood sloka, summary, past sittings; reels data (feed pages, a reel, similar, book-reel look, verse reels, saved, comments, creators — not the media; pictures are disk-cached via `AppImage`); Sakha's status/conversation/profile (sending needs the network); plans, subscription, referral card, shared link content, tickets, developer chat.
- **Chant-along recordings are files** (`MalaAudioCache`, `<app support>/mala_audio`), not in the response box. `ChantMalaPlayer` opens a kept file (`setFilePath`) and saves one it played from the link; a kept file that won't play is deleted and the link tried. Named by a hash of the link **without the query** (signature changes hourly, upload key doesn't) + its extension (iOS needs it); `.part` then rename; one download per recording; ≤ `maxSavedRecordings` (6), least recently played out. The catalogue's, not personal — **sign-out leaves them**. Tests pass `malaAudioCacheProvider.overrideWithValue(null)`.
- **Fetching ahead — `OfflineWarmer`** (`services/offline_warmer.dart`, `offlineWarmerProvider` read once in `app.dart`; signed-in only). Runs `warmDelay` (10 s) after sign-in/launch, on foreground, on reconnect — each at most every `warmInterval` (6 h); a language change forces a pass. A pass fetches: every book, its languages and contents (short works saved whole via `BookRepository.shortWork`); **on Wi-Fi, queues every book for the offline library** (`BookSyncManager.syncBook`; a queued unit carries on over mobile data unless `syncWifiOnly`); calendar from `calendarMonthsBefore` 1 to `calendarMonthsAfter` 3 + upcoming, in the app language; etiquette today / list / items older than `itemRefreshAfter` 7 days; prayers — the list, then each prayer not saved or older than `itemRefreshAfter`; the "Chant now" mantra (today's practice then its page), and **on Wi-Fi its recording**; mantra categories/list, book-reel look, issues, languages, summary, favourites, mood sloka.
- **A pass that never reached the server isn't counted** (the book list goes first; if its saved time didn't move the pass stops and stays due). Every step swallows its own failure; one pass at a time; `warmConcurrency` bounds parallelism. **The reels feed is not fetched ahead** (the ranking reads a feed request as "shown"); neither are the verse page, search or Sakha.
- **Wiped on sign-out** (`AppSession.clear` → `ResponseCache.clear`, `offlineWarmedAt`).
- **Not covered:** anything done offline (like, comment, ticket, favourite) fails and isn't queued — only the routine and chant record have queues; search; a reel's video; unvisited calendar months.

## Three languages

Three settings, each its own, stored on the device (`providers/language_settings_provider.dart`, `models/language_settings.dart`); changing one never changes another.

| Setting | Drives | Default |
|---|---|---|
| **App** | UI locale (`appLocaleProvider`); only a language with an ARB (else the choice is kept and the UI stays in a shipped language) | device language if shipped, else English |
| **Reading** | translation, meaning, purport (`readingChainProvider`: reading → app → en) | device language, else English |
| **Speaking** | spoken meaning/purport (`speakingChainProvider`) — **nothing in the reader uses it now** | device language, else English |

First value: stored → the account's choice (app and reading only) → phone language → English. App and reading are also sent to the account, best effort; speaking has no server field. Sanskrit verse text is always Sanskrit. Settings → **Languages** has a picker each.

Why: the phone changes language at once and tells the account afterwards (`LanguageSettingsNotifier._set`, unawaited), so a call in between came back in the old language and the book read **one change behind**. **Picking a rendering under "Compare translations" is dropped when the reading language changes** (`ChapterReadView`).
- **Home follows the reading language:** `homeFeedProvider` watches `readingChainProvider`; the call is `GET /home?languages=hi,en` (`HomeService.fetch`), same reason. (1) The saved copy is language-matched (`BoxKeys.lastHomeLanguages`, `HomeService.cached(languages:)` returns nothing for another) — offline, the provider falls back to the copy in any language rather than an error. (2) While the new language loads the old screen stays (`HomeTab` `skipLoadingOnReload: true`). (3) A late answer can't overwrite a newer choice (`ref.mounted` + chain check). `_refetchServerShaped` no longer touches Home. A language with no published text for a verse shows English (imported rows stay hidden until an admin publishes — root [CLAUDE.md](../CLAUDE.md)).

## Spoken meaning and purport (voices) — not used by the reader at present

The reading player no longer speaks; this engine is still built and reachable from Settings → Voices. `TtsEngine` interface: `SherpaTtsEngine` (offline neural), `PlatformTtsEngine` (`flutter_tts`), `AdaptiveTtsEngine` (neural when a voice is installed for the language, else the phone's, and again from the failed chunk if neural dies). ## Session and tokens

- **One session singleton** owns both tokens; nothing else reads/writes them. Tokens in **`flutter_secure_storage`**; non-sensitive session state in **`hive_ce`**.
- **Refresh token 1 year**, re-issued on every use. **Access token 7 days**, renewed about daily, silently — never an auth interruption, re-login prompt or failed request caused by rotation. (Decided by the owner: a long access token swapped daily; a stolen one stays valid up to a week, no revocation list; sign-out-everywhere revokes refresh tokens.)
- **Only the server can end a session, with one answer: a 403 with code `UNAUTHENTICATED` given to the refresh call itself.** Nothing else signs anyone out — no signal, timeout, 5xx, 429, a proxy's code-less 403, unreadable body, restart. The refresh token is kept; the request fails with its own kind (`network`, `timeout`, `server`, `rateLimited`), never `unauthorized`. `AppSession.restore` reads the secure store only and **doesn't compare token dates with the phone's clock**.
- **"Not signed in"** = 403 `error.code` `UNAUTHENTICATED` (missing/expired/invalid access token; expired/revoked/replayed refresh). A 403 with another code (`FORBIDDEN`) is `FailureKind.forbidden`: never refreshes, never ends a session. An old 401 reads the same as `UNAUTHENTICATED`. A bare 403 with no JSON envelope is not ours.
- **Refresh-and-replay** (`ApiClient._onError`, streams included — `_readErrorBody`): one `POST /auth/refresh` through a second Dio with no interceptors, shared by every call that failed together (`_refreshInFlight`; a refresh token spends once), replayed once with the new bearer (`_retriedFlag`). Outcomes (`_Outcome`): **renewed**, **rejected** (403 `UNAUTHENTICATED` — clears the session only if the stored refresh token is still the one sent), **unavailable** (everything else — session stays).
- **Renewing before it lapses** (`ApiClient.renewAccessTokenIfDue`, never throws): on launch and resume (`app.dart` observer) and alongside requests; reads the access token's own `iat` (payload only, **unverified, used for timing, never trust**); renews at `AppConfig.accessRenewAfter` (1 day) or half its life if shorter; a failure isn't retried for `renewRetryAfter` (15 min), a success not for a day (in memory — a wrong phone clock can't make it refresh every request). Not a timer: a closed app doesn't renew; the first call after a long absence takes the 403 path.
- **Sign-in and sign-out send no bearer and are never answered with a refresh** (`_noBearerPaths`; the API refuses an expired bearer even on a public route). Logout is public — its body's refresh token is the credential.
- **A lost reply doesn't cost the session:** the server accepts a spent refresh token again for `REFRESH_REUSE_GRACE_SECONDS` (5 min) ("Sessions and tokens" in [backend/CLAUDE.md](../backend/CLAUDE.md)).

## Authentication

**Google and Apple sign-in only** — no email/password, no OTP. Sign-up carries a client attestation token ([backend/CLAUDE.md](../backend/CLAUDE.md)).

### Signing in from the previous app

The previous app (**Sadhana**, same bundle id, Laravel server) left an access token on the phone. At launch, with nobody signed in, this app trades it for a session so an updater isn't asked to sign in. Server half: "Legacy users" in [backend/CLAUDE.md](../backend/CLAUDE.md).

- **Token:** `shared_preferences` key `token` (`LegacyKeys.token`; the plugin stores the old app's write as `flutter.token`). `LegacyTokenStore` (`core/session/legacy_token_store.dart`) returns it trimmed, null unless 10–300 chars (`AppConfig.legacyTokenMinLength/MaxLength`), never throws. **This app writes nothing there**; its own tokens use `SecureKeys`. The old app's sign-out wipes that slot, so a token here means signed-in at update.
- **When:** `main.dart` awaits `LegacySignIn.instance.run()` after storage + Firebase, before `runApp`; a signed-in phone reads and sends nothing. **The one place launch waits on the network** (else welcome/sign-in flash past someone signed in), capped at `AppConfig.legacySignInTimeout` (12 s) and **cancelled** via `ApiCancelToken` (a late reply can't start a session over one made with Google meanwhile).
- **Call:** `POST /auth/legacy` (`ApiPaths.signInLegacy`) with `legacyToken` + the sign-in fields; attested, no bearer (`_noBearerPaths`). `AuthService.signInWithLegacyToken` uses the same `_open` as Google/Apple (session, push registration, `onboardingSeen` true unless the account is new/201).
- **What each answer does to the token** — by the API's *code* (`ApiCodes`), never status alone (a proxy's 401/409 says nothing): **removed** on 403 `UNAUTHENTICATED` and 409 `CONFLICT` (a same-email account here is linked to the old user; the person's one Google/Apple tap lands in it — "An account here that already has the email" in [backend/CLAUDE.md](../backend/CLAUDE.md)); **kept** on everything else (no signal, timeout, 429, 5xx, 503 `LEGACY_UNAVAILABLE`, refused attestation, 400, bare 401/409, `FORBIDDEN`, 200 without tokens). Nothing is shown either way; no new text.
- **Signing out is final:** `signOut()` and `deleteAccount()` remove the old token too. **An account can have no email** (the API sends none rather than a made-up one): `AppUser.email` empty, `IdentityHeader` draws the name alone.

## Sharing, deep links and refer and earn

`lib/core/share_links.dart` is the **only parser** of a shared link (same grammar as backend and website): `https://hariharibol.com/{shloka|naam|darshan|satsang}/<code>`, `hariharibol://…`, `hariharibol://open?path=/…`; any other host refused. `services/deep_link_service.dart` listens with `app_links` (cold + running), dedupes, asks the API what a code is (`ShareService.resolve`) and pushes the route through `PushLinks`; a path reaching the router is claimed in `app_router.dart`'s redirect and handed to the same service. A gone link says `shareLinkGone`. An invitation is held in `BoxKeys.pendingInvite` until signed in, then presented once; **a typed code on the Refer screen is the fallback** (no deferred deep link promised).

Share studio `views/share/share_studio_view.dart` (card painted by `widgets/share/share_card.dart`, exported to PNG, `share_plus`); entry points: verse block, Home verse card, mantra screen, reels. Refer screen `views/premium/refer_view.dart` (Settings). Android App Links (`autoVerify`) + `hariharibol` scheme and iOS `applinks:hariharibol.com` are declared but **only verify once the API serves the association files** (`APPLE_TEAM_ID`, `ANDROID_CERT_SHA256`). 35 strings (`share*`, `refer*`, `settingsRefer`). This part was written without a Flutter SDK — its generated l10n files were hand-edited; run `pub get`, `gen-l10n`, `analyze`, `test` first.

## Firebase and signing

Both are secrets, not in the repo; a fresh clone builds without them (the google-services plugin applies only if `android/app/google-services.json` exists, release signing only if `android/key.properties` does, `FirebaseService` records a failed init).

| What | From | Lands at |
|---|---|---|
| Firebase config | `flutterfire configure --project=hari-hari-bol` | `android/app/google-services.json`, `ios/Runner/GoogleService-Info.plist`, `lib/firebase_options.dart` |
| Signing keystore | `../hariharibol-local-secrets/` (irreplaceable; identical copy in old `sadhana`) | `android/app/key.jks`, `android/key.properties` |

- **Identity is fixed:** `com.sss.ramkrishnahari` on both platforms, Firebase project `hari-hari-bol` — matches the store listings and keystore; don't let `flutter create` reset it.
- **Google Sign-In needs the signing SHA registered** or Android fails with bare `DEVELOPER_ERROR`: add a machine's debug SHA with `firebase apps:android:sha:create <androidAppId> <sha>`; **Play App Signing re-signs the upload**, so register the Play Console SHA-1 too. The Gradle plugin turns `google-services.json` into `default_web_client_id`; iOS needs `REVERSED_CLIENT_ID` as a URL scheme. Backend `GOOGLE_CLIENT_IDS` / `APPLE_BUNDLE_IDS` must list these ids.
- **iOS minimum 15.0** (Firebase SDK) in `Runner.xcodeproj` and `Podfile`; both must agree. *"requires minimum platform version 15.0 … but this target supports 13.0"* on a laptop run is a stale generated `ios/Flutter/ephemeral/Packages/FlutterGeneratedPluginSwiftPackage/Package.swift` (SPM rewrites it to 13.0): run `flutter pub get` (or `flutter build ios --config-only --simulator`) and run again; don't lower 15.0 or hand-edit that file.

## Releasing the iOS app (Xcode Cloud)

An Xcode Cloud workflow archives to TestFlight when `main` is merged into `production` ("Releasing" in [deploy/README.md](../deploy/README.md)). **The workflow lives in Xcode / App Store Connect, not the repo**; the repo holds what it relies on. Continues the Sadhana listing (1.0.26+26, same bundle id).

In the repo: `ios/Runner/Runner.entitlements` (Release: Sign in with Apple, push `production`, App Attest `production`, Associated Domains `applinks:hariharibol.com`), `RunnerDebug.entitlements` (Debug/Profile, same four, `development`; Profile uses App Attest while development-signed), `Info.plist` (`UIBackgroundModes` `remote-notification`, `ITSAppUsesNonExemptEncryption` = false — **owner should confirm that declaration is true**), `Runner.xcodeproj` (`CODE_SIGN_ENTITLEMENTS` per config, `CODE_SIGN_STYLE = Automatic`, `DEVELOPMENT_TEAM = V2LNA795Y9`), `ios/ci_scripts/ci_post_clone.sh` (installs Flutter per `.flutter-version`, restores `GoogleService-Info.plist`, writes dart-defines, `flutter build ios --config-only`).

- The app needs all three entitlements (Apple sign-in, FCM, App Check `AppleAppAttestProvider`) or sign-in/push/App Check silently fail. **Team is the old app's `V2LNA795Y9`** (CALLVCAL TECHNOLOGY PRIVATE LIMITED); the App Store Connect record must be in the signing team; on another team change it locally in Xcode and don't commit.
- **Flutter is kept off Swift Package Manager in CI** (`flutter config --no-enable-swift-package-manager`): Xcode Cloud disables auto package resolution and fails on any package without a committed `Package.resolved`. Laptops still use SPM.
- **Build number is Xcode Cloud's `$CI_BUILD_NUMBER`**; marketing version is `pubspec.yaml` `version:`. Set the workflow's **Next Build Number** above the highest ever uploaded (pubspec `2.0.0+31`; last Sadhana upload 26).

**Set up once, by hand:**
1. Apple Developer → Identifiers → `com.sss.ramkrishnahari` (team `V2LNA795Y9`): enable **Push Notifications, Sign in with Apple, App Attest, Associated Domains** (cloud-managed profiles carry only what the App ID has; a missing one fails the export). The extension's App ID `com.sss.ramkrishnahari.NotificationService` needs none.
2. Firebase: upload an **APNs authentication key** (Project settings → Cloud Messaging) or no push reaches iPhones; register the iOS app for **App Attest** under App Check.
3. App Store Connect → Xcode Cloud: grant the GitHub app access to the repo.
4. Create the workflow: workspace **`app/ios/Runner.xcworkspace`**, scheme **Runner**; **start condition Branch Changes → `production` only**; action **Archive – iOS**, post-action **TestFlight Internal Testing**; env vars (tick *Secret*): `GOOGLE_SERVICE_INFO_PLIST` (required: `base64 -i ios/Runner/GoogleService-Info.plist | pbcopy`), optional `API_BASE_URL` (https only; unset = production), `GOOGLE_SERVER_CLIENT_ID`, `GOOGLE_IOS_CLIENT_ID`, `FLUTTER_VERSION`.
5. Set **Next Build Number**.

## Large screens, foldables and TV

The app adapts to the window, not the device: `core/layout/adaptive.dart` — `WindowSize` (compact < 600, medium < 840, expanded < 1200, large), `AdaptiveLayout.of(context)` (class, hinge rect, half-open posture, TV flag), `ContentWidth` (centres in a max width; no-op on a phone or with a hinge), `TwoPane` (splits at the hinge, else by ratio), `ContentWidths` (`reading` 720, `regular` 880, `wide` 1180, `reel` 480).

- **Navigation:** compact = floating `GlassNavBar`; medium+ = `widgets/common/side_nav.dart` (rail on medium, 264 px column from expanded; Sakha's button on top), fed the same `NavItem`/`NavHero` list. The tab beside the rail gets its own `MediaQuery` (room left, hinge shifted). Reels stays a 480 px column on black. Every pushed screen is wrapped in `ContentWidth` in `app_router.dart`; Home is two columns from expanded (or per-screen when a vertical hinge splits the window).
- **Foldables:** hinge/posture from `MediaQuery.displayFeatures`; `resizeableActivity="true"`; `configChanges` has screenSize.
- **TV:** `MainActivity.kt` answers `hariharibol/device` `isTv` from `UiModeManager`; manifest has `LEANBACK_LAUNCHER` and `touchscreen`/`leanback`/`microphone` `required=false`. On TV the focus ring is always drawn, text ≥ 1.15×, the side column is a focus group. TV banner is the launcher icon (a 320×180 `banner` is wanted).
- **Desktop:** `AppScrollBehavior` (mouse/trackpad drag, scroll bars). `macos/` is a generated runner (bundle id `com.sss.ramkrishnahari`, window 1280×820, min 420×640) — not built; several plugins unchecked for macOS.
- **Tests:** the default test window (800×600) is *medium* — a phone-bar test must set `tester.view.physicalSize` first (see `auth_flow_test.dart`). **Not done:** list/detail two-pane in the library; landscape redesign of intro / chant / share studio; width-limited dialogs and sheets.

## Readers' own mantras

Jap tab → **Add your mantra** (`AddMantraCard` in `sadhana_tab.dart`, route `/mantras/add` — **registered before `/mantras/:slug`** or "add" is read as a slug). Backend: "Readers' own mantras" in [backend/CLAUDE.md](../backend/CLAUDE.md). **No string says "AI"** — "we found these"; `ownMantraWellKnownNote` says mantras must be well-known ones.

- **One screen, four stages** (`views/mantra/add_mantra_view.dart`, `providers/own_mantra_provider.dart`: `OwnMantraStage` ask → finds → adding → added). The reader types or **says** the mantra (`widgets/mantra/mantra_text_input.dart`, `speechInputProvider`, app language); words go into the box and are **never searched by themselves** — they press Find. Finds are `SuggestionTile`s: new/shared ones tick (≤ 5, `ownMantraChosenCount`); `yours`/`catalog` are plain rows with an open arrow. "Add chosen" sends **only the numbers** (`OwnMantraService.create(suggestionId, picks)`); `own_mantra_results.dart` says what became of each and ends with Done. The provider is kept alive while a creation runs.
- **Pictures:** a private mantra shows its picture atop its page (`mantra_picture_header.dart`: public picture the server found, or the reader's upload, which wins) and on the Jap list. "Change picture" (`own_mantra_actions.dart`, only the maker, `Mantra.isMine`) uses `chatImagePickerProvider` and `PUT`s bytes (`ApiClient.putBytes`); "Remove" for any private mantra held, asks first. `Mantra.imageCacheKey` = the URL **without its query**.
- **Private mantras cannot be shared** (`Mantra.isPrivate` hides Share; server 404s) and carry a "Private" label (never colour alone).
- **Failures are worded by the app, by code** (`widgets/mantra/own_mantra_problem.dart`): not usable, busy ("for now"), too many, expired finds, not available, picture too large/unusable, offline. **410 and 413 are read from `failure.statusCode`** (`ApiClient._kindFor` maps them to `unknown`). Mic and picture notices reuse the chat's strings; refused mic has `ownMantraMicDenied`.
- **After any change** `OwnMantraService` wipes cached mantra copies (`LocalStore.deleteWithPrefix(BoxKeys.mantraCachePrefix)`) and `invalidateMantras` refreshes list, categories and named detail pages — or the offline-first Jap tab would show the old list. Home is not refreshed. No widget test for `MantraDetailView` with a private mantra.

## Prayers

Short devotional texts to say or read along (morning and evening prayers, before meals, to the guru, to a deity, aartis, peace chants), each with an optional meaning per verse. **Code written and analysed (`flutter analyze` shows no error or warning from it); no test was written, nothing has run on a phone or against a live API, and the 27 `prayers*` strings are AI-drafted in 11 languages, not read by a native speaker.** Entry: Home card (`widgets/dashboard/prayers_entry_card.dart`, after the etiquette card) → `/prayers` (`views/prayers/prayers_view.dart`: a category bar (`prayer_category_bar.dart`, only when there is more than one category, filters on the phone) and tiles (`prayer_tile.dart`)) → `/prayers/:id` (`prayer_view.dart`). Routes `AppRoutes.prayers` / `prayerPattern` / `prayerPath(id)`. Data: `models/prayer.dart`, `services/prayer_service.dart` (`GET /api/app/prayers` and `/:id`, each sent `?languages=` from the reading chain), `providers/prayer_provider.dart`. Category names from l10n by id (`prayersCategory*`, `prayer_category_label.dart`), falling back to the API's name.

- **The server says which scripts a prayer can be shown in; the phone chooses** (`core/format/prayer_scripts.dart`). Each script is `original` (the verse as written), `stored` (text the server holds for every verse; `en` is the Roman letters) or `rule` (converted on the phone by `fromDevanagari`, a verse's own `renderings` entry winning over the rule). A script of a kind the app doesn't know is skipped, not an error. `resolvePrayerScript`: the reader's last pick if this prayer offers it → the first of reading → app → English the prayer can be shown in (the original when it lists that language) → the original. A verse with no writing in the chosen script falls back to the original, never a blank. `PrayerRenderer` remembers each (verse, script) for as long as the prayer is on screen.
- **Three device prefs** (`providers/prayer_prefs_provider.dart`, `LocalStore`, kept across sign-out like the other reading settings): `BoxKeys.prayerScript` (one pick for every prayer; a prayer that lacks it falls through), `prayerMeaningsOpen` and `prayerShowOriginal` (both default off). The script bar (`prayer_script_bar.dart`, pinned under the app bar when the prayer offers a script besides the original) names each script by its language's own name (`languagesProvider`) and `prayersScriptOriginal` / `prayersScriptRoman`.
- **The verse block** (`prayer_verse_block.dart`): a number badge, the verse, and a meaning row that opens and closes with a chevron. Which meanings are open is a set of verse ids held by the page, seeded from `prayerMeaningsOpen`; the app-bar button opens or closes all (and writes the pref), and the settings sheet's switch is applied by a listener. **Roman text takes the transliteration face and everything else the verse face**, judged from the text (`isRomanPrayerText`) and not from the script's code, because a stored `hi` is Devanagari and a stored `en` is Roman. With "Show the original" on, the original sits above in a muted smaller line (only when the shown script isn't the original). Text size follows `readingFontSizeProvider`; the settings sheet (`prayer_settings_sheet.dart`) reuses `readingSettingsTitle` and the font-size strings.
- **Offline:** `OfflineWarmer._warmPrayers` fetches the list and each prayer not saved or older than `itemRefreshAfter`, in the reading chain; the list and a prayer are shown saved-first (`savedThenFresh`). A prayer never opened and never fetched ahead has no copy offline.
- **Not done / unverified:** the app bundles no Indic fonts, so how Bengali, Tamil, Telugu, Kannada, Malayalam, Gujarati, Gurmukhi, Odia and Assamese read depends on the phone's fonts and the `rule` conversion's output — neither has been seen on a device. No push or deeplink for prayers.

## Testing traps

- **A `LocalStore` / Hive write started under a widget test's fake clock never finishes** and holds the store's write lock, so the *next* test's `setUp` (`LocalStore.clear()`) hangs — it looks like a hang, not a failure. Hence: `keepStoresInMemory()` / `keepStoresInStore()` from `test/support/chant_stores.dart` (chant progress / pace / ledger), `ReadingPlaceStore.keepInMemory()`, in-memory providers for word meanings, nothing written from `RoutineNotifier.build()` for an empty routine, and for routine saves `settleSaves` (queues probe writes and pumps until they land, ending with one real-time write via `runAsync`).
- `test/auth_flow_test.dart` stubs the `connectivity_status` channel (a signed-in app listens to it); `signOut(seenIntro: true)` default; call `SplashGate.instance.open()` in `setUp`; default window is *medium* (set a phone size for the bar).
- Time-of-day failures at baseline: `routine_check_test.dart` "a task from before times were kept can be given one" fails after noon (picker defaults to PM); `routine_test.dart` "shows a strip of days with a tilak on Ekadashi" fails on an Ekadashi day (counts one tilak per chip, the selected-day banner draws another).
